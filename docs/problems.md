# Журнал проблем и работы с ИИ-ассистентом

Окружение: Node.js v24.22.0, Vite 8.3, React 19.3, React Router 7.18, TypeScript 7.0, Google Chrome.
Проверка выполнялась вручную и автоматическими сценариями в Chrome (Puppeteer): задание 3 — 18/18, задание 4 — 19/19.

## Часть 2. Работа с ИИ-ассистентом

Работа выполнялась вместе с ИИ-ассистентом **Claude Code** (модель Claude Opus 5.5): ассистент писал код по заданию,
каждый результат проверялся сборкой, запуском в браузере и автоматическими сценариями.

### Случай 1. Проверка слоя API

- **Промпт:** «Проверь мой слой API: не бросаются ли исключения наружу? Все ли ответы проверяются type guard? Что произойдёт, если сервер вернёт HTML или пустое тело?»
- **Ответ (кратко):** исключения возможны в трёх местах — `fetch` (нет сети, отмена), `res.json()` (пустое тело, HTML) и
  ошибки сервера без JSON. Все три обёрнуты: `send()` превращает сбой `fetch` в `ApiError`, `readBody()` возвращает `undefined`,
  `errorFrom()` берёт `message` из тела или текст статуса. DELETE (204) обрабатывается отдельной функцией без чтения тела.
- **Проверка экспериментом в браузере:** успех; `getCourse(999)` → `404 «Запись не найдена»`; повторный код → `409`; `credits: 0` → `422`;
  отмена через `AbortController` → `«Запрос отменён»`; сервер остановлен → `«Нет связи с сервером…»`;
  HTML вместо JSON (адрес API направлен на сам Vite, ответ `200 text/html`) → `«Сервер вернул данные неожиданной формы»`.
- **Итог:** принято, во всех сценариях функция вернула `Result` с `ok: false`, приложение не упало.

### Случай 2. Проблемы в хуке useCourses

- **Промпт:** «Найди в этом хуке возможные проблемы: гонки запросов, утечки, неправильные зависимости useEffect.»
- **Замечания и решения:**
  - *Гонка:* без отмены медленный ответ старой страницы мог бы перезаписать новую. — Уже решено: `AbortController` + проверка
    `controller.signal.aborted`. **Проверено** с `DELAY_MS=1500`: запрос стр. 2 отменён, показана стр. 3.
  - *Зависимости:* `[page, limit, version]` — полные; `reload` обёрнут в `useCallback`, поэтому не меняется между рендерами. Принято.
  - *Где хранить номер страницы:* в компоненте, а не в хуке — иначе страница не смогла бы после удаления последней
    записи перейти на предыдущую (типичная ошибка из методички). Хук только получает `page` параметром.
  - *Утечка setState после размонтирования* — в React 18+ предупреждения больше нет, а ответ всё равно игнорируется по `aborted`.

### Случай 3. Сценарии ручного тестирования формы

- **Промпт:** «Составь список сценариев ручного тестирования формы: корректные данные, пустые поля, очень длинные значения, повторная отправка, ошибка сервера.»
- **Выполнено:** все сценарии (см. таблицу в отчёте). Сценарий «повторная отправка» выявил ошибку — два POST при двойном клике (проблема №1).
- **Предложенное исправление** (флаг в `useRef`) проверено тем же сценарием, а не на слово: после правки уходит один POST.
- **Почему не только `disabled` на кнопке:** блокировка срабатывает лишь после перерисовки, а два клика в одном такте
  успевают раньше — поэтому нужна синхронная проверка через ref.

### Случай 4. Импорт из react-router или react-router-dom

- **Вопрос:** методичка предупреждает, что документация React Router может предлагать пакет `react-router`.
- **Проверка:** установлен `react-router-dom@7.18`; в v7 он реэкспортирует всё из `react-router`. Импорт из `react-router-dom`
  работает (сборка и все маршруты проверены), а прямой импорт `react-router` означал бы зависимость от пакета, которого нет в `package.json`.
- **Итог:** оставлен `react-router-dom`.
